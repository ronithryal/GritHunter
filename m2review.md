## Bug 1 — `rateLimitCheck.ts:116` — Dead `incr` call inflates counter on blocked requests

```typescript
if (count > maxQueries) {
  // Decrement the counter we just over-incremented, then reject
  await redis.incr(rlKey); // no-op counter fix not needed; count is already over
  return { allowed: false, reason: 'rate_limit', ... };
}
```

**The comment says "decrement," the code calls `incr`.** On every blocked request, the counter gets bumped by 1 unnecessarily. The two comments directly contradict each other. The line does nothing useful — just remove it. The `RedisClient` interface doesn't even expose `decr`, so the stated intent (undo the over-increment) was never achievable.

The practical impact is low since the key already has a TTL and the count is already over limit — but it's wrong and confusing. Fix: delete line 116.

**Status: FIXED** — dead `redis.incr(rlKey)` removed.

## Bug 2 — `parseEnrichment.ts:67` — URL not trimmed before validation

```typescript
if (isValidUrl(item.url)) {
  signal.url = item.url;
}
```

`URL_PATTERN = /^https?:\/\//` is anchored with `^`. If Perplexity returns `" https://github.com/user "` (leading/trailing whitespace — not uncommon in LLM output), the pattern fails and the URL is silently dropped. The signal is kept but with no URL. This is a quiet data quality degradation.

Fix applied:
```typescript
const rawUrl = typeof item.url === 'string' ? item.url.trim() : item.url;
if (isValidUrl(rawUrl)) {
  signal.url = rawUrl; // trimmed value stored, not the original
}
```

**Status: FIXED** — URL trimmed before validation; trimmed value stored.

## Bug 3 — `perplexityClient.ts` — `extractCost` relies on unverified response field path

```typescript
function extractCost(responseJson: unknown): number {
  const usage = res.usage as Record<string, unknown> | undefined;
  const cost = usage.cost as Record<string, unknown> | undefined;
  return typeof cost.total_cost === 'number' ? cost.total_cost : 0;
}
```

If `usage.cost.total_cost` isn't the actual field name in the Perplexity Agent API response, this silently returns 0 on every call. The spend cap (`rateLimitCheck`) would then never increment — effectively disabled.

**Status: VALIDATED** — confirmed via live probe (2026-04-21) that the real response path is `usage.cost.total_cost`. Comment added to `extractContent` documenting the confirmed envelope shape:

```
// Confirmed via live probe (2026-04-21):
//   - Top-level `output_text` is ABSENT in real responses
//   - Real path: output[n].type === 'message'
//               → content[m].type === 'output_text'
//               → content[m].text  (the synthesized answer)
```

## Structural Issue — `agentSearch` boundary clarified

**Previous state:** `agentSearch(sanitizedQuery: string)` accepted a raw string, making it easy for M3 routes to accidentally pass raw user input without mode-specific wrapping.

**Fix applied:** `agentSearch` now accepts `SearchInput`:

```typescript
export type SearchInput =
  | { type: 'nl'; value: string }
  | { type: 'profile'; value: string }
  | { type: 'repo'; value: string };

export async function agentSearch(
  input: SearchInput,
): Promise<PerplexityCallResult>
```

An internal `buildSearchQuery(input: SearchInput): string` function constructs the mode-specific query. The route can no longer accidentally pass a bare string — the type system prevents it.

## Informational: TOCTOU on spend cap

```typescript
const currentSpend = await redis.get(spendKey);   // read
// ...
await redis.incrbyfloat(spendKey, estimatedCostUsd); // write
```

Between read and write, a concurrent request could push spend past the cap without being blocked. The cap can be exceeded by N-1 concurrent requests that all read under-cap before any of them write. For v1 with low traffic this is fine — the cap is soft by design and the window is daily. Treat $10 as a ~$10–$11 ceiling in practice. Deferred.

## Informational: `classifyInput.ts` doesn't handle `www.github.com`

Design.md regex includes `(www\.)?` in the pattern. The current implementation strips `https://` but then checks `startsWith('github.com/')` — so `www.github.com/username` is classified as `nl`. Low real-world risk (browsers normalize to non-www). Deferred to v1.1.
